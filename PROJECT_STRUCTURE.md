# Структура проєкту

## Призначення

Репозиторій містить звіт і артефакти практичної роботи № 1 з дослідження HTTP, HTTPS, cookies та CORS. Документи оформлено за схемою: мета або запит, команда, фактичний результат, аналіз і висновок.

## Фактична структура

```text
T01/
├── README.md, ANSWERS.md, PR1.md, PROJECT_STRUCTURE.md
├── cookies.txt                         # Cookie Jar із тестового запуску
├── level_1/
│   ├── t1/preparation.md
│   ├── t2/{GET,POST,PUT,DELETE}/*.http # Запити та збережені відповіді
│   └── t3/devtools_analysis.md         # Аналіз Network
├── level_2/
│   ├── RESULTS.md
│   ├── t1/t_2_1.md                     # GET і POST
│   ├── t2/t_2_2.md                     # Заголовки та статуси
│   ├── t3/t_2_3.md                     # Авторизація
│   └── t4/t_2_4.md                     # Таймінги
└── level_3/
    ├── t1/t_3_1.md                     # TLS і redirect
    ├── t2/t_3_2.md, cookies.txt        # Cookie Jar
    ├── t3/t_3_3.md                     # Атрибути cookies
    └── t4/t_3_4.md                     # CORS preflight
```

## Інструменти та сервіси

- `curl` для консольної діагностики;
- VS Code REST Client для HTTP-файлів;
- браузер DevTools для вкладки Network;
- `https://dummyjson.com/` для REST і авторизації;
- `https://httpbin.org/` для статусів, cookies та CORS;
- Git для збереження результатів.

## Вимоги до матеріалів

- Команди мають бути відтворюваними та містити потрібні заголовки.
- Фактичні відповіді не слід замінювати очікуваними.
- Динамічні значення (токени, IP, дата, час) потрібно маскувати або позначати як результат конкретного запуску.
- Скриншоти додаються до `level_1/t3`, якщо вони потрібні умовами здачі.

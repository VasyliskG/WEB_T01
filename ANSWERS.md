# Відповіді на контрольні питання

## 1. Стартовий і статусний рядки

Стартовий рядок запиту описує дію клієнта: `GET /resource HTTP/1.1`. Він містить метод, URI та версію HTTP. Статусний рядок відповіді описує результат сервера: `HTTP/1.1 200 OK`. Він містить версію HTTP, тризначний код і текстову фразу.

## 2. Safe та idempotent

Безпечний метод не змінює стан ресурсу на сервері. Ідемпотентний метод дає той самий запланований ефект після повторного виконання. `GET` є safe та idempotent; `POST` не є safe і зазвичай не є idempotent; `PUT` і `DELETE` не є safe, але є idempotent.

## 3. Групи кодів стану

`2xx` означає успіх, `3xx` — перенаправлення, `4xx` — помилку запиту клієнта, `5xx` — помилку сервера. `201 Created` означає створення ресурсу, `301 Moved Permanently` — постійне перенаправлення, `401 Unauthorized` — відсутні або недійсні облікові дані, `403 Forbidden` — доступ заборонено, `404 Not Found` — ресурс не знайдено, `500 Internal Server Error` — внутрішня помилка сервера.

## 4. Content-Type та Accept

`Content-Type` описує формат тіла поточного повідомлення, наприклад `application/json`. `Accept` перелічує формати, які клієнт готовий отримати. Сервер використовує ці заголовки для content negotiation і повертає найбільш придатне представлення або помилку, якщо формат не підтримується.

## 5. TLS Handshake

Клієнт надсилає `ClientHello`, сервер відповідає `ServerHello`, передає сертифікат і сторони узгоджують ключі. Після повідомлень `Finished` HTTP-дані передаються зашифрованим симетричним алгоритмом. Відкритий HTTP не забезпечує конфіденційність, цілісність або автентичність сервера, тому дані можна перехопити чи змінити.

## 6. TTFB

Time To First Byte — час від початку запиту до отримання першого байта відповіді. Він охоплює мережеві затримки, DNS, встановлення TCP, TLS для HTTPS, передавання запиту та очікування обробки на сервері. Content Download відбувається після TTFB.

## 7. HttpOnly, Secure та SameSite

`HttpOnly` не дозволяє JavaScript читати cookie і зменшує ризик викрадення сесії через XSS. `Secure` дозволяє надсилати cookie лише через HTTPS і зменшує ризик перехоплення через HTTP. `SameSite` обмежує міжсайтове надсилання cookie та зменшує ризик CSRF. Ці атрибути не замінюють захист від самої XSS або правильну серверну авторизацію.

## 8. CORS preflight

Preflight — це `OPTIONS`-запит браузера перед основним кроссайтовим запитом. Він потрібен для non-simple запитів, зокрема коли використовується `PUT`, `DELETE`, нестандартний `Content-Type` або заголовок `Authorization`. Сервер має підтвердити дозволене джерело, методи й заголовки через `Access-Control-Allow-*`.

# Практична робота № 1

## Дослідження мережевих протоколів засобами інструментів розробника

## Мета

Дослідити HTTP/HTTPS-запити та відповіді, CRUD-операції REST API, TLS Handshake, cookies і CORS за допомогою `curl`, REST Client/HTTP-файлів та DevTools.

## Використані сервіси й інструменти

- ОС: Linux.
- CLI: `curl 8.18.0`.
- REST API: [DummyJSON](https://dummyjson.com/).
- Echo-сервіс: [httpbin.org](https://httpbin.org/).
- Інструменти: VS Code REST Client, браузер DevTools, Git.

Запити виконуються до відкритих сервісів і не потребують API-ключів. Значення IP, часу відповіді, `Date`, `ETag` і кешування можуть змінюватися під час повторного запуску.

## Рівень 1. HTTP, REST і DevTools

### CRUD-запити

| Метод | Endpoint | Фактичний результат |
|---|---|---|
| `GET` | `/products/1` | `200 OK`, отримано JSON товару |
| `POST` | `/products/add` | `201 Created`, відповідь містить `id: 195` |
| `PUT` | `/products/1` | `200 OK`, поле `title` оновлено |
| `DELETE` | `/products/1` | `200 OK`, відповідь містить `isDeleted: true` |

Команди та заголовки збережено у HTTP-файлах у [level_1/t2](level_1/t2). Аналіз браузерного запиту `GET /products` містить статус, заголовки й таймінги у [devtools_analysis.md](level_1/t3/devtools_analysis.md). Скриншот мережевої активності: [devtools_network.png](level_1/t3/devtools_network.png).

## Рівень 2. Консольна діагностика

Виконано:

- отримання двох користувачів через `GET`;
- перевірку `POST /posts/add`;
- `HEAD`-запит через `curl -I`;
- перевірку статусів `404` і `500` через httpbin;
- отримання Bearer-токена та запит `/auth/me`;
- вимірювання DNS, TCP, TLS, TTFB і загального часу.

Фактичний перший POST-запит до `/posts/add` повернув `400`, оскільки заголовок був записаний із зайвим початковим пробілом. Це виправлено в описі [t_2_1.md](level_2/t1/t_2_1.md); правильний формат заголовка: `-H "Content-Type: application/json"`.

Зафіксовані метрики одного запуску:

| DNS | TCP | TLS | TTFB | Загальний час |
|---:|---:|---:|---:|---:|
| 0.027689 с | 0.057328 с | 0.089722 с | 0.133509 с | 0.138653 с |

## Рівень 3. HTTPS, Cookie та CORS

- TLS-з'єднання встановлено за TLS 1.3; сертифікат `dummyjson.com` перевірено через Google Trust Services, узгоджено `TLS_AES_256_GCM_SHA384` та `X25519MLKEM768`.
- HTTP-запит перенаправляється кодом `301` на HTTPS.
- Cookie Jar зберігає `session_key=lab1_token` і `user_role=student` у Netscape-форматі та успішно передає їх повторному запиту.
- `Set-Cookie` перевірено з атрибутами `Secure`, `HttpOnly`, `SameSite=Strict`.
- CORS preflight завершився `200 OK`; сервер дозволив джерело, `POST`, `Content-Type` і `Authorization`.

## Висновки

Під час роботи досліджено повний цикл HTTP-взаємодії: формування запиту, заголовки, тіло, коди відповіді та час виконання. Практично підтверджено різницю між HTTP і HTTPS, роль TLS-сертифіката, правила збереження cookies та механізм CORS preflight. Усі результати слід трактувати як знімок конкретних запусків: публічні API можуть змінювати заголовки, IP-адреси й час відповіді.

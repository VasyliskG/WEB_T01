# Аналіз заголовків безпеки Cookie

## 1. Запит

Для перевірки атрибутів безпеки cookie виконано запит:

```bash
curl -i "https://httpbin.org/response-headers?Set-Cookie=session_id=xyz789%3B%20Path%3D%2F%3B%20Secure%3B%20HttpOnly%3B%20SameSite%3DStrict"
```

Параметр `Set-Cookie` передає серверу cookie `session_id=xyz789` з атрибутами `Path=/`, `Secure`, `HttpOnly` і `SameSite=Strict`.

## 2. Результат

У відповіді сервера отримано заголовок:

```text
set-cookie: session_id=xyz789; Path=/; Secure; HttpOnly; SameSite=Strict
```

Це саме значення також повернуто у JSON-відповіді:

```json
{
	"Set-Cookie": "session_id=xyz789; Path=/; Secure; HttpOnly; SameSite=Strict"
}
```

Отже, наявність і значення атрибутів підтверджено:

| Атрибут | Значення | Призначення |
|---|---|---|
| `Secure` | присутній | Cookie надсилається лише через HTTPS. Це зменшує ризик перехоплення під час передачі через незахищене HTTP-з'єднання. |
| `HttpOnly` | присутній | Забороняє доступ до cookie через JavaScript. Це зменшує ризик викрадення cookie під час XSS-атаки. |
| `SameSite` | `Strict` | Обмежує надсилання cookie у кроссайтових запитах. Це зменшує ризик CSRF-атак. |

## 3. Аналіз захисту

### `Secure`

Атрибут `Secure` дозволяє браузеру надсилати cookie тільки через захищене HTTPS-з'єднання. Він захищає від перехоплення cookie в мережі під час використання незашифрованого HTTP або небезпечної публічної мережі. Цей атрибут не захищає від XSS-атак.

### `HttpOnly`

Атрибут `HttpOnly` забороняє клієнтському JavaScript читати cookie через `document.cookie`. Тому він ускладнює викрадення сесійного ідентифікатора через XSS. Водночас `HttpOnly` не запобігає самій XSS-атаці та не забороняє браузеру автоматично надсилати cookie.

### `SameSite=Strict`

Режим `Strict` обмежує надсилання cookie у запитах, ініційованих з іншого сайту. Це зменшує ризик CSRF, коли зловмисний сайт намагається виконати дію від імені авторизованого користувача. Залежно від сценарію навігації та вимог застосунку цей режим може обмежувати роботу кроссайтових переходів.

## Висновок

Сервер успішно повернув cookie `session_id=xyz789` з атрибутами `Secure`, `HttpOnly` і `SameSite=Strict`. Разом вони захищають cookie від перехоплення через незахищений канал, доступу клієнтського JavaScript і надсилання у більшості кроссайтових запитів.
